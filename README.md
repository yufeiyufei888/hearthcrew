# HearthCrew · 炉火伙伴

HearthCrew 是一个面向 Minecraft 1.21.1 / NeoForge 21.1.249 的实验性 AI 生存伙伴模组。它把三个独立的 GPT-5.6-Luna/high 会话接入三个服务器控制的 `ServerPlayer`，让伙伴能够在原版生存规则下观察环境、决定目标、执行连续工作并与玩家及队友协作。

> **当前状态：0.3.2 开发版。**
>
> 这是一份公开的开发快照，不代表完整生存通关、长期稳定性或所有第三方 Mod 兼容性已经验收。自动测试、受控客户端测试和真实长期陪玩是不同的证据层级，请阅读“验证边界”后再使用。

[![Verify development build](https://github.com/yufeiyufei888/hearthcrew/actions/workflows/verify.yml/badge.svg)](https://github.com/yufeiyufei888/hearthcrew/actions/workflows/verify.yml)

## 项目定位

HearthCrew 的核心原则是：模型负责目标、分工和风险判断；本地执行器负责把已经批准的工作持续完成。世界修改必须经过服务器线程上的唯一执行器，并以真实的库存、方块、实体、位置或原版事件作为完成依据。

每个伙伴拥有独立身份、会话、任务和记忆：

- **Ember**：稳定的服务器玩家身份，负责自己的自主目标，也可以承担防卫和协作工作。
- **Moss**：独立规划和执行，不共享另一个角色的身体执行权。
- **Flint**：独立规划和执行，普通材料准备优先在自己的任务内完成。

三个名字只是默认伙伴身份，不是固定职业。Luna 可以根据真实状态重新分配采集、制作、建设、探索和协作任务。

## 已实现能力

下面的能力已经存在于当前代码和协议中，但每项仍有不同的验收范围。

### 玩家身体与生命周期

- 使用服务器控制的 `ServerPlayer`，进入原版玩家实体列表和实体跟踪。
- 支持固定名字、UUID、保存、重连、死亡、掉落、重生、床出生点和维度核对。
- 支持原版 `/tp Ember`、`/kill Moss` 以及常见玩家命令的名字解析。
- 一个身体只有一个执行后端和一个当前动作；迟到请求、旧身体和旧回合不能重新取得执行权。
- 暂停、急停、取消和世界退出会清除残留输入，健康的已接受身体工作不会因为模型回合超时被重放。

### 移动、通行与有限开路

- 使用原版物理进行步行、台阶、跳跃、下降、游泳和上岸。
- 目标到达会核对实际脚位、目标高度和连续落地稳定性，不能只因为水平位置接近就报告完成。
- 长距离工作采用分段导航，搜索预算、未加载区域、预算耗尽和确认受阻分别记录。
- `EXCAVATE` 只在动作授权范围内进行有限安全开路；不传送、不搭桥、不盲挖脚下、不突破保护区。
- 采掘接近、掉落回收、工位接近和让路使用统一的站位和碰撞检查。

### 采集、拾取与工具准备

- `COLLECT_RESOURCE` 按新增物品数量持续执行；会连续选择候选、接近、采掘、回收和补充候选。
- 支持原木、圆石、煤和粗铁等已注册资源来源。
- 采掘前检查完整背包、工具适用性、耐久、掉落资格和输出空间。
- 在授权范围内可以补齐普通工具准备，例如利用真实材料和服务器配方制作替代工具。
- 方块破坏和掉落拾取分开记录；队友拾取、掉落合并、满包和掉落消失不会被错误计入原采掘者产出。
- 额外开路预算由原任务共享，重规划或切换候选不会重新获得预算。

### 制作、工位与加工

- 使用服务器实际配方和实际材料，不通过配方名称凭空生成物品。
- 支持自身或公共工作台的接近、使用和制作核验。
- 支持公共箱子、容器的受限存取和交接提案。
- 支持普通熔炉的投料、原版 tick 加工、订单等待和实际产物收取。
- 投料成功与得到产物是两个状态；加工尚未完成时不会提前报告完成。
- 工具、工位和准备步骤属于原任务的连续阶段，不会因为制作一次木棍或更换一次工具就创建新的长期任务。

### 施工、保护与协作

- `PLACE` 和有限 `BUILD` 使用真实点击面、材料消耗、支撑、碰撞、站位和保护规则。
- 玩家建筑、私人容器和未知归属位置保守保护。
- 协作提案可以表示让路、材料交付、工具交接和分工；“收到”不等于执行完成。
- 普通木材加工、逐块进度和换槽静默记录，只有依赖解除、公共设施就绪、持续受阻、危险或玩家询问才公开交流。
- H 面板可以选择小队、Ember、Moss 或 Flint 作为任务接收者。

### 控制器、协议与 H 面板

- 本地 TypeScript 控制器负责三个独立 Luna/high 会话、任务调度、恢复和证据记录。
- 协议包含世界、伙伴、身体代次、动作身份、请求指纹和后端能力握手。
- 协议版本为 6；0.3.2 增加精确移动完成和 Numen 后端状态声明。
- H 面板包含小队总览、任务详情、真实对话、背包、设置、诊断、暂停和急停。
- 对话页只显示伙伴与玩家的真实公开发言；工具回执、内部推理和恢复日志进入诊断。
- 控制器只监听本机回环地址，配对令牌保存在被忽略的本地运行目录，不进入源码。

## 验证结果与边界

当前公开快照的证据分成四类：

| 层级 | 当前结论 |
| --- | --- |
| TypeScript 控制器 | 当前 0.3.2 定向回归通过，覆盖协议、任务调度、恢复、UI 数据、迟到调用和去重。 |
| Java / NeoForge | 生产模组与核心代码可编译打包；针对性 Java 检查通过。 |
| 无界面 GameTest | 覆盖精确移动、有限开路、预算、保护、恢复和黄色旧提示抑制等受控场景。 |
| 受控客户端 / Luna | 有早期受控采木、制作、交付和三人协作闭环证据；不能推导出长期自主生存或完整通关。 |

下列内容明确尚未作为本项目的已完成能力声明：

- 全新普通生存世界的长期自主生存。
- 下界、要塞、末地、龙战和完整返程。
- 120 分钟稳定性 soak、第二种子复验和所有第三方 Mod 兼容。
- 农业、狩猎、船只完整驾驶和复杂多方块设施的全链路验收。
- 任意洞穴、任意地形和所有水域路线的可靠通行。
- 模型在真实网络、长时间运行和电脑异常后的无条件恢复。

自动测试证明的是对应执行场景，不等同于“AI 已经能够独立通关”。欢迎通过新的可复现场景补充证据。

## 快速开始

### 环境

- Minecraft 1.21.1
- NeoForge 21.1.249
- Java 21
- Node.js 24
- Windows PowerShell（启动脚本目前以 Windows 为主要目标）

### 构建模组和控制器

```powershell
git clone https://github.com/yufeiyufei888/hearthcrew.git
Set-Location hearthcrew

# Java 模组和核心
.\scripts\build.ps1 -Tasks ':kernel:test', ':mod:build'

# 控制器
Set-Location bridge
npm.cmd ci
npm.cmd test
```

构建产物默认位于 Gradle 的 `mod/build/libs/`。公开仓库不提交 JAR；安装时请使用与源码提交对应的本地构建产物，并确认 NeoForge 与其他 Mod 版本一致。

### 启动本地控制器

回到仓库根目录后，可使用：

```powershell
Set-Location ..
.\启动炉火伙伴.cmd
```

首次使用需要通过项目文档中的专用登录和 pairing 流程完成本地控制器配置。不要把 `pairing.json`、认证文件、令牌或个人存档复制进仓库或 issue。

### 在游戏中加入伙伴

进入安装 HearthCrew 的世界后，在聊天框执行：

```text
/hearthcrew join Ember
/hearthcrew join Moss
/hearthcrew join Flint
```

之后可以使用模组状态命令或按 **H** 打开中文面板。H 面板支持查看目标、阶段、当前步骤、真实对话、背包摘要和诊断状态；任务发送可以选择小队或指定伙伴。

## 测试

常用检查：

```powershell
# 控制器完整回归
Set-Location bridge
npm.cmd test

# 回到根目录运行 Java 构建和无界面 GameTest
Set-Location ..
.\gradlew.bat build :mod:runGameTestServer --no-daemon --console=plain
```

测试世界、运行目录和日志必须与普通开发源码分离。GameTest 可以验证已知场景的执行事实，但不能替代真实客户端、真实 Luna、兼容性和长期运行验收。

## 架构概览

```text
Minecraft / NeoForge Server
        │
        ├─ HearthCrew Mod + ServerPlayer bodies
        │       └─ single executor / vanilla physics / receipts
        │
        └─ local bridge (TypeScript)
                ├─ protocol + pairing
                ├─ task stages + recovery
                ├─ five game tools
                └─ three independent Luna/high sessions
```

后端通过 `CompanionBackend` 适配；当前生产路径使用固定版本的 Numen 玩家身体和 HearthCrew 自有的授权、任务、保护及结果核验。Numen 自带模型规划和自动对话入口不会成为第四个决策者。

## 隐私和安全边界

HearthCrew 面向本地单人世界设计：

- 控制器默认只监听本机回环地址。
- pairing 令牌和登录状态只写入本地被忽略目录。
- 不应提交个人存档、认证、模型原文、私人聊天、运行日志或电脑路径。
- AI 不能调用任意命令行、文件、浏览器、联网工具或控制台命令来修改世界。
- 所有世界修改必须经过服务器线程、保护规则和真实结果核验。

如怀疑令牌泄露，请停止控制器、删除本地 pairing 状态并重新完成登录；不要在 issue 中粘贴令牌或完整日志。

## 路线图

近期重点是让已有主世界能力持续、可解释地推进：

1. 扩大普通生存资源、工位、施工和回收的真实客户端验收。
2. 完成长时间自主运行、第二种子和兼容性检查。
3. 改善探索、战斗、水域和农业等能力的执行闭环。
4. 在证据充分后再评估下界、末地和完整通关能力。
