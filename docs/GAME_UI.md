# 0.1.4-dev 行为补充

三名伙伴优先独立游玩、完成手头任务。普通请求加入待办；说“立即执行”“先停下”“改派”可明确打断。关闭自主不会清除玩家任务，待命/急停会取消待办；暂停保留待办。队友先协商，不能强派忙碌伙伴。

H 小队页会显示“迎敌反击 / 危险撤退 / 确认安全”及真实原因。自卫由本地身体处理，无需等待 Luna；危险解除后核对原任务再恢复。模型仍负责长期目标和具体生存策略。

伙伴已经是 `hearthcrew:companion` 实体，具有碰撞、受伤、背包和死亡。输入 `/hearthcrew locate Ember` 可查看位置和 UUID；输入 `/hearthcrew tp Ember` 可将自己传送到伙伴附近，名字支持 Tab 补全，需原版作弊/管理员权限，支持跨维度。原版当前维度选择器示例：`/tp @s @e[type=hearthcrew:companion,name=Ember,limit=1]`。直接 `/tp Ember` 按原版玩家名解析，不能代表该实体不存在。

新版本轮只编译打包，新增行为需手动试玩。

# 游戏界面（开发版）

## 三名 Luna 的公开聊天

Ember、Moss、Flint 各有独立 `gpt-5.6-luna + high` 会话和记忆。H → 诊断显示名字、会话 ID 和实际配置。重启后会话可以重建，身份、角色和长期记忆按世界与伙伴 ID 恢复。

公开发言同时进入原版聊天栏与 H → 对话，显示真实名字、接收者及回复关系。“聊天：开/关”只隐藏原版聊天，H 历史与队友通信继续；偏好保存在当前实例 `config/hearthcrew-chat.txt`。H 显示最近 30 条，控制器持久记录完整消息；重进世界不把历史刷回原版聊天栏。

T 栏示例：`@Ember 你在做什么`、`Moss，附近安全吗`、`@Flint 需要我帮忙吗`、`@小队 帮我采木`。名字后使用空格、逗号或冒号；普通未点名聊天不传给模型。同名伙伴无法唯一点名时会提示，不猜接收者。控制器离线时点名提示重试。

提问先按对话处理；明确任务由接收者 Luna 引用原玩家消息申请改派，控制器走已有玩家任务流程。全队消息仅派发一次；派发中断或身体/控制状态变化时保留待核对，不自动重复执行，可核对后重新发一条指令。

工作中的伙伴可短暂交流，但交流回合不能提交动作或直接改派任务。协商使用 `discuss_work`，正式团队工作仍需正常任务仲裁。每轮最多两条、每条 200 字；四层纯消息往返后等待新玩家消息或游戏进展。手动暂停、待命、急停时保存消息，不启动自主回复。

本功能尚未完成新版本真实模型契约或游戏测试，不能据此声称三人已可靠自然协作。

进入安装 HearthCrew 的独立测试世界后，按 **H** 打开炉火伙伴面板。若输入法出现拼音候选，先切为英文输入再按 H；面板里的命令仍支持中文。快捷键可在 Minecraft 控制设置里更改。

首页默认打开“入门”：列出控制器启动、官方登录、PCL 进入世界、诊断检查，以及已实现的斜杠命令。页面下方的“复制接入提示词”会把接入说明复制到剪贴板，方便粘贴给 Codex；复制本身不会安装 MCP 或改变桌面配置。当前后台控制器供 H 面板使用，桌面 MCP 接入仍须依照 [桌面接入说明](DESKTOP_MCP.md) 配置，并确保同一状态目录只有一个控制器。

- 小队：查看三名伙伴的位置、生命、饥饿和当前动作。
- 任务：查看真实动作的执行、完成、取消或待核对状态。
- 对话：查看自己的指令、伙伴公开回复和任务进展。
- 背包：点击左侧伙伴查看实际物品，只读展示。布局与玩家 E 键背包一致：下方单独显示 9 格快捷栏（0–8），上方显示 27 格主背包（9–35）；装备栏/副手在服务端已知时单独显示，不把快捷栏和背包合并成一块 36 格网格。
- 设置：查看每个角色实际使用的模型、推理档位和服务等级。
- 诊断：查看游戏、控制器、App Server 和角色连接状态。
- 入门：教程、接入提示词和斜杠命令示例，支持滚动查看。

底部输入中文任务后点击“发送”，指令会交给全队。当前还没有单人选择发送。暂停保留当前动作，恢复后继续；急停立即取消本地动作并停止规划。急停时控制器离线也会停止本地身体，但需要重连才能重新下令。面板本身不暂停单人世界。

伙伴加入世界后默认开启自主游玩：没有玩家任务时，控制器会按角色目标安排可执行的生存工作；自主状态仍受本地安全、玩家命令和团队任务仲裁。可在控制页使用 `auto_on` / `auto_off` / `standby`，也可在聊天中使用 `/hearthcrew autonomy on`、`/hearthcrew autonomy off` 和 `/hearthcrew standby`。`auto_off` 只关闭自主规划并保留正在执行的玩家任务；`standby` 让伙伴暂时待命并结束普通自主工作；新的玩家指令会清除待命状态并重新取得 OWNER 控制权。当前自主能力仍在逐步接入，先覆盖生存开局、营地选择、补给和受边界限制的探索，不能把控制器在线或模型回复当成真实动作完成。

发送后自动切换到对话页，立即显示你的原文和“发送中”；服务端确认后显示“已接受”，失败或超时会保留原因。接受不代表身体任务完成。相同文字的不同请求按请求 ID 区分；同一小队命令不会因分发给三个角色而重复显示三遍。伙伴公开回复显示身体名称与角色，任务进展与错误也留在历史中，新增消息自动滚到末尾。

当前已实测的例子：“三人各自采集自己面前的一块橡木，制作成四块橡木木板，然后停下待命。”此例是在明确放置了橡木的开发场景中通过，不能当作普通生存自主基地已完成。

连续采木也已在三人实际客户端通过：“三人各自使用连续采木动作，采集三根橡木，保留在各自背包中。每人完成后待命。”当前只识别附近橡木/白桦的简单直树干，建议每次 2..4 根；复杂树、跨多棵树的批量采集仍在开发。找不到可确认的树或受到阻挡时会报告原因，不能仅凭聊天回复认定完成。

普通生存、PCL 安装与辅助模组组合仍待逐步测试。已知限制：界面外观仍较简洁；全队指令会显示各角色接收记录；伙伴偶尔会重复回答；大批量采集、完整物流和通关策略还在补齐。

开发者可用 `:mod:runPlaytest` 打开本仓库独立实例，并用 `-PhearthcrewPlaytestSave=存档名` 重开已有测试存档、`-PhearthcrewPairing=绝对路径` 连接本地控制器。它不创建测试物品或覆盖存档；控制器仍需按 [MCP 说明](DESKTOP_MCP.md) 启动。受控测试记录见 [界面证据](../evidence/P2_GAME_UI_2026-09-05.md)。

本页对应未测试开发构建；本次仅完成编译打包，未执行单元测试、GameTest、模型探针、真实客户端或长时间稳定性测试。自主生存、完整物流、下界/末地通关以及辅助模组兼容仍属于待验收能力。开启自主不会解除急停；已急停时先恢复。
