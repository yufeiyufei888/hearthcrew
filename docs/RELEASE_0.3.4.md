## 问题、修改与证据

| 问题 | 本版修改 | 针对性证据 |

| 队友无法供给仍永久等待材料 | 供给者受阻或故障也通知依赖方；保留库存门槛，去重唤醒 | 不足量且生产者受阻只唤醒一次 |
| 新玩家任务被旧阶段挡住 | 空闲且明确受阻的身体允许接续正常新指令；有效身体动作、暂停动作及未知效果仍需核对 | 新指令接续、历史保留和不重放回归 |

| 最近候选失败结束整个采集 | 保留失败地形指纹，过滤已破坏及仍受阻候选，继续其他合法候选 | 封闭近矿与可达矿共存，真实取得16煤炭 |

| 阶段/协作字段允许不完整参数 | stageId非空；按operation声明阶段、目标和协作所需字段；公开当前后端实际资源获取范围 | TypeScript及工具契约检查 |
| 扫描版本变化反复唤醒 | 比较稳定资源事实；固定扫描起点的真实地形改变才触发通路事件，换版本和移动邻域不冒充地形改善 | 相同扫描保持事实；移除非资源墙体改变地形事实且不制造新资源 |
| 新版本继续旧等待或显示过期动作 | 首次连接对受影响的0.3.3等待重新评估，保留目标/历史；H显示复核期限、实际采集步骤和取得量 | 一次性迁移、暂停保护、真实步骤与历史分离回归 |
| 候选过滤增加服务器负担 | 仅对已有失败记录计算邻域指纹；未失败候选不重复读取整片邻域 | 实现与最终Java编译核验，未宣称完成性能基准 |

等待复核是有限纠正，不是定时制造模型活跃。两次评估后若仍无安全可执行方案，会继续核对真实条件并说明阻碍；玩家仍可下达新任务。`unknown_effect`不自动重放，玩家暂停、急停和待命保持优先。

自然树规则继续保守：树根、树冠来自有界已加载扫描；分支、截断边界和未知归属不能自动当作天然树。准备快照新增扫描完成、未加载边界、观察数和合格数，不能从“看见原木”推断“已经允许破坏”。

游戏完全退出后，备份旧HearthCrew JAR、安装清单、控制器源快照和启动配置，替换为唯一0.3.4 JAR。固定执行库不变；其他Mod、存档、认证、伙伴记忆和原任务历史保留。控制器同步更新后重启，游戏由用户从PCL手动启动。

具体提交、SHA-256、检查日志及安装结果保存在本机忽略目录 `.artifacts/releases/0.3.4/`。回退时先退出Minecraft并停止本项目控制器，按安装记录恢复旧JAR和旧控制器源/启动配置，再编译旧控制器。不要删除伙伴历史或重新导入库存。
