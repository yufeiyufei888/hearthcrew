# 0.3.2 修复计划：准确到达、受阻恢复和定向任务

状态：代码及针对性检查完成，结果见 RELEASE_0.3.2.md；安装另以实际安装记录为准，尚未完成真实陪玩验收。

## 证据与原因

- 本次 MOVE 将不同高度的横向到达记成成功。上游明确报告忽略 Y，但适配层没有复核三维位置。
- blocked 阶段只写入任务历史，没有转入控制器的结构化等待；因此有具体受阻原因仍累计为 no_plan。
- scan_ready 对所有等待类型生效，重复扫描可以唤醒同一失败，但不清除相关旧调度状态。
- Numen 的 MCP 120 秒心跳不代表 HearthCrew 的三个 Luna 会话；旧提示的翻译键也没有包含在裁剪依赖中。
- H 发送操作固定走小队分配，查看某个伙伴并不会改变收件人。

## 实施顺序

1. 保存本次退出前证据。仅修改 HearthCrew 适配层，保持固定 Numen 依赖及私人世界数据。
2. MOVE 复核实际三维脚位及稳定落地。禁止上游自动忽略高度后报成功。接通受原有保护与共享预算约束的 EXCAVATE，明确目标是脚位、只开路，不代表取得矿物。
3. blocked 阶段进入明确等待；允许一次替代方案评估。重复扫描不解除等待，相关事实变化、玩家指令或恢复操作才能重新评估。无计划与真实模型连接故障分开。
4. 对 0.3.1 的相关停工记录进行一次持久化重新评估，保留目标和原始回执；暂停、急停、待命和未知修改优先，绝不重放旧动作。
5. 屏蔽属于 HearthCrew 本地伙伴的旧 MCP 心跳提示，H 继续显示真实连接与恢复状态。其他独立 Numen 使用不受此抑制影响。
6. H 增加显式收件人选择和针对当前伙伴的重新评估入口。消息携带伙伴身份、去重及接受状态，不能静默广播。
7. 运行相关控制器回归、移动/受限开路 GameTest、Java 与 TypeScript 编译。已知成功场景必须实际成功；不调用真实模型、不启动客户端、不使用私人存档。
8. 检查游戏退出，备份安装 0.3.2、同步控制器并核对哈希。若相关检查未通过，不安装。

## 验收与边界

- 不同 Y 到达不能成功；合法路径必须到达；开路保护、预算和取消有效。
- 具体受阻不升级整名角色故障；替代评估有限；旧结果不复活；重连不重复应用恢复。
- 暂停与待命不被修复迁移覆盖；定向任务不进入其他伙伴队列。
- 黄色通知抑制以本地受控伙伴存在为条件，客户端退出后解除。
- 不承诺任意地形均可通行，不通过无限调用 Luna、提高移动速度、传送或补库存制造进展。
