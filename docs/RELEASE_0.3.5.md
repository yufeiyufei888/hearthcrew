# HearthCrew 0.3.5：修复采矿候选与无动作恢复

**开发版，尚未完成真实陪玩验收。** 保留三个独立 `gpt-6-luna / high`、执行协议6、现有0.3.x世界、原任务与记忆。固定执行库仍为 `947f0064f3374adc0341e61687215ae32ea9765a`；本版修改适配层，不替换上游，不接管0.2.x身体。

## 退出前观察

本轮挂机后期三名伙伴长时间没有新的身体任务，游戏时钟与连接仍正常，不能解释为菜单暂停。此前日志还显示：扫描已经确认可采矿源，底层任务却返回没有可达矿物；同一失败消耗多次准备步骤；小半径采木因树冠在范围外被拒绝；三维移动与底层列坐标回退不一致。有限等待复核耗尽后，界面将实际受阻与模型没有动作混为一类，随后持续写入未形成新评估的复核记录。

这不是单一模型响应慢的问题。私人日志、原始聊天、存档及角色标识保留在本机忽略目录，不进入提交。

## 问题、修改与证据

| 问题 | 修改 | 核验 |
|---|---|---|
| 扫描有目标，底层采矿索引仍返回空 | 将授权扫描的真实位置补入原生候选，再运行原生工具、液体、采掘成本与不可用候选检查；不增加工作范围 | 128个更近的受保护矿物与16个合法矿物并存，单次请求真实取得16煤炭，保护矿物全部保留 |
| 相同候选失败反复启动准备 | 记录失败候选及局部条件，继续其他候选；空索引失败也有明确的已尝试范围，保持原任务预算 | 被水覆盖的矿物停止于一次执行步骤，零产出、矿物未被破坏；不消耗16次同样的准备步骤 |
| 小半径切断树根或树冠验证 | 使用有界、已加载的树形验证邻域；仅原授权范围内原木进入采集候选 | 半径4场景取得4原木，范围外上层原木保留 |
| 普通移动走到同列不同高度就停止 | 路径搜索与完成核验共用三维脚位；最终必须稳定落地，禁止列坐标回退冒充到达 | 有合法阶梯时到达高处实际脚位；无支撑的高处目标准确失败、不改地形 |
| 两次纠正后长期泛化为等待模型 | 保留阶段或最新当前身体终态中的真实阻碍；没有事实阻碍时，在旧回合结束后进行一次独立会话恢复，保留原目标与结果 | 独立会话、无重叠回合、迟到工具拒绝与不重放回归；新会话仍无计划则明确故障，不无限建会话 |
| 恢复期间暂停或换身体被旧快照覆盖 | 会话创建前后核对世界、身体、控制代次及实际执行权 | 创建期间发生暂停：不启动新回合、不产生动作、不将暂停写为无计划故障 |
| 等待耗尽后持续产生伪复核记录 | 未变条件的复核额度持久化，耗尽后只检查事实；不同物品或有效条件变化可重新评估，改阶段标题不能重置额度 | 未变条件只有两次评估；暂停冻结、重连保留额度、新条件及新任务仍可接续 |
| 旧失败覆盖后续成功 | 只用当前意图、当前身体的最近非历史终态解释阻碍 | 已完成动作之后的旧失败不能继续显示为当前阻碍 |
| 旧0.3.4故障继续进入新版 | 首次新握手只安排一次现状评估，保留目标与历史，不提交历史动作 | 迁移一次性、未知效果不重放、暂停/急停/待命优先 |
| 标签与握手版本残留 | Mod、控制器、后端标识与教程统一0.3.5；旧控制器明确拒绝连接 | 模型契约、版本握手及生产包检查 |

候选顺序在任务阶段边界生成；树形验证缓存同一树根与已读事实，避免逐tick重复排序与整棵扫描。未做性能基准，不能据此宣称所有卡顿已消失。

- TypeScript编译通过，模型契约、后端能力、控制器、恢复、等待、看板、阶段及握手相关回归 **160/160通过，无跳过**。使用假模型与临时日志，没有真实Luna调用。旧阶段中的泛化模型等待不冒充真实资源或通路阻碍，仍可进入一次独立会话恢复。
- 隔离无界面GameTest **6/6通过，无跳过**。四个实际成功场景：连续16煤炭、范围边界采木、精确高处移动、高处工作台真实制镐；两个准确停止场景：危险矿物、无支撑高处目标。成功场景没有把合理失败计作通过。
- 连续采煤用603个有效执行tick，原版拾取证据和库存均确认16；小半径采木用282tick，确认4；高处工位准备用70tick，实际消耗3圆石、2木棍，获得并装备1石镐。这些是受控场景的时间，不能推算真实地形提速比例。
- Java21生产JAR编译与包内容单独核对。实验场景、测试角色、私人日志与认证不进入JAR。
- 保留测试启动时的原始失败证据：旧实验文件依赖宿主却未被独立构建排除，以及新测试命名空间缺少空结构。补齐测试集成后重跑同一六个场景，没有放宽验收条件。
- 未启动客户端、使用私人存档测试、调用真实Luna。

原版速度、挖掘时间、拾取距离、保护区、实际库存与共享预算没有放宽。旧公开CI守卫失败、真实长期自主发展、通关与120分钟稳定性仍不是本版已通过项目。无法安全推进的身体会保留具体阻碍并释放执行权；本版不保证在任何地形都能完成任务，也不靠无限重试制造活跃。
